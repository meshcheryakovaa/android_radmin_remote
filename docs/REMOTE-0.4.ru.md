# Класс: миниатюры и Veyon, 1.0.0

Обновите основное приложение поверх 0.3.0 / 0.4.0. Package и постоянный сертификат сохранены; VPN, ключи Veyon и настройки остаются на месте.

## Настройка

1. Подключите Radmin VPN и войдите в нужную сеть. У ПК должен появиться установленный канал.
2. На ПК должен работать Veyon Service, обычно TCP 11100, с настроенными правами доступа.
3. В приложении откройте **Настройки → Доступ к установленному Veyon**. При ключевом входе импортируйте приватный RSA PEM-ключ, укажите имя ключа (например `teacher`). На ПК должен быть соответствующий открытый ключ с тем же именем. Группа доступа к приватному ключу в Windows управляет чтением локального файла, её не нужно вводить как имя пользователя Android-клиента. Пользователь при ключевом входе необязателен, если правила доступа Veyon не требуют определённого имени. Для Windows logon нужны пользователь и пароль Windows.
4. Настройте интервал миниатюр в миллисекундах, ширину и качество JPEG, нужную Radmin-сеть и фильтр включённых ПК. Сохраните.
5. Откройте **Класс**. Миниатюры заполняются автоматически. На планшете 30 плиток помещаются без прокрутки; при большем количестве доступна прокрутка, загружаются находящиеся на экране ПК.

Radmin Server использует другой протокол. Этот клиент подключается к установленному Veyon без дополнительного агента, WebAPI или websockify. Сокеты рабочего стола проходят через существующий VPN-маршрут 26/8; `protect()` для них не вызывается.

## Обновление и медленная сеть

Интервал 250–60000 мс — минимальное время между обновлениями одного ПК, не гарантия получения всех 30 экранов за это время. Обновления последовательные: снимок одного ПК → маленький JPEG → закрытие соединения → следующий ПК. Текущие миниатюры остаются видны во время обновления остальных. Таймаут всего снимка — 15 секунд; после ошибки повторная попытка для этого ПК откладывается минимум на 15 секунд, остальные продолжают обновляться.

Для сетевого снимка запрашивается 8-битный RGB332 и zlib вместо 16-битного RGB565 режима просмотра. Ширина 160–480 px и качество JPEG 25–80% определяют сохранённое изображение сетки после декодирования. Они сокращают память и передачу внутри приложения; серверный framebuffer по RFB пока получается в исходном разрешении. Повторное подключение требует аутентификации и полного снимка; на очень медленной сети полный круг может быть длительным.

В native-клиенте не удерживаются 30 полноразмерных framebuffer. Полный кадр есть у одного снимка либо у выбранного просмотрщика; маленькие JPEG существуют в RAM WebView. Оригинальные кадры и миниатюры не пишутся в файлы или диагностику. Сохранённые пароль/приватный ключ — в EncryptedSharedPreferences.

## Действия по нажатию

- **Просмотр** открывает один экран без передачи ввода.
- **Управление** открывает экран и включает ввод после первого проверенного кадра. Касание/перетаскивание, аппаратная клавиатура, колесо и специальные клавиши доступны в просмотрщике. Отключение управления отпускает удерживаемые клавиши/мышь.
- **Заблокировать / Разблокировать** отправляет штатную Veyon ScreenLock feature-команду. Это блокировка Veyon, с отдельной командой снятия, а не выход из Windows. Протокол не подтверждает применение блокировки, поэтому сообщение приложения говорит только об отправке команды. Доступ определяется настройками/плагином Veyon на ПК.

До открытия просмотра/управления текущий запрос миниатюры отменяется и его сокет закрывается. Новые миниатюры не запрашиваются. Возврат в класс закрывает полноразмерный сеанс, затем возобновляет очередь. Уход с вкладки, сворачивание приложения и потеря VPN останавливают запросы. Устаревшие ответы от прежней очереди/identity не устанавливаются.

## Ограничения и проверка

RFB 3.7/3.8, Veyon security 40, ключ RSA SHA-512 / logon RSA-OAEP, raw/copyrect/zlib, DesktopSize/LastRect. До 8192 px на сторону и 8 294 400 пикселей, с общим бюджетом памяти устройства. Нет звука и буфера обмена; передача файлов описана в разделе 0.4.2 ниже. Для 30 ПК на маленьком телефоне миниатюры будут очень мелкими; планшет предпочтительнее.

Пользователь подтвердил получение изображения от реального ПК на 0.4.0. Для 0.4.1 автоматические проверки: 30 синтетических ПК, последовательность и справедливость обхода, отсутствие ввода при просмотре, пауза в просмотре/управлении, отмена медленного запроса, возобновление после закрытия, изменение интервала/качества, lock/unlock и размеры 1280/1536/390/320 px. `scripts/test-classroom-ui.cjs` воспроизводит браузерный стенд с Playwright; screenshots `v041-*-synthetic.png` явно синтетические.

JVM loopback проверяет RGB332+zlib, отсутствие следующего запроса кадра в snapshot-режиме, lock/unlock без запроса framebuffer и сравнение feature-пакетов с настоящим Qt QDataStream Qt_5_5. Тесты никогда не обращаются к реальным ПК или пользовательскому VPN. Массовый обход и ScreenLock нужно принять на установленном Windows Veyon.


## 0.4.2: пропорции, общие команды и заблокированные экраны

Рамка миниатюры всегда 16:9. Число строк и ширина плиток рассчитываются по фактическому числу отображаемых ПК, высоте экрана и панели команд. Плитки последней строки тоже делят всю ширину. Исходное изображение другого формата вписывается внутрь рамки без обрезки и искажения. При более чем 30 ПК доступна прокрутка.

Верхняя строка: выключить, перезагрузить, заблокировать, разблокировать, открыть сайт, передать файл. При нажатии фиксируется список отображаемой группы (активный фильтр сети/включённых ПК). Перед отправкой показываются конкретные адресаты; выключение/перезагрузка подтверждаются одной кнопкой для всей группы. Для сайта вводится HTTP(S)-адрес, для файла — системный выбор документа Android. Скрытые фильтром ПК в список не попадают. Офлайн-ПК из отображаемой группы получают результат недоступности, остальные продолжают обрабатываться.

Отправка последовательная, без автоматических повторов команд, с отдельным результатом по каждому ПК и возможностью отменить оставшуюся очередь. Получатели фиксируются по RID/IP, экземпляру VPN и текущему Activity generation. Смена VPN, сворачивание приложения, потеря интерфейса или отмена останавливают очередь и закрывают активный сокет/поток файла. Данные доступа нельзя менять до завершения очереди. Команды и файл не сохраняются на диск приложения.

Протокол Veyon feature messages: PowerDown, Reboot, ScreenLock и DesktopServices OpenWebsite; для файлов — FileTransfer start/chunk/finish/stop с UUID передачи. Один файл до 200 МБ, потоковыми блоками 64 КиБ; без Base64 и загрузки всего файла в RAM. Папка назначения задаётся настройками Veyon на принимающем ПК (обычно домашняя папка пользователя). Существующие файлы не перезаписываются, автоматическое открытие отключено. Во время файла миниатюры приостанавливаются для освобождения канала, затем продолжаются. Отмена при оборванном соединении может оставить неполный файл на принимающей стороне.

Veyon не присылает подтверждение применения этих команд или записи файла: результат **«команда отправлена»** означает завершение отправки в соединение, а не доказательство выключения, открытия сайта или получения файла. Для применения должны быть установлены/разрешены соответствующие плагины Veyon и подходящие права/пользовательский сеанс на ПК. Не используйте это как подтверждение доставки.

Блокировка больше не отключает очередь снимков на native-стороне. После одиночной команды очищается задержка ошибочной попытки для этого ПК и выполняются дополнительные запросы свежего кадра (с учётом запуска Veyon worker), затем продолжается заданный интервал. Пока новый кадр не получен, прежний не удаляется. В приложении нет искусственной картинки «заблокировано»: миниатюра показывает только framebuffer, который отдал Veyon. Если Veyon не отдаёт изображение своей блокировки или службы на конкретном ПК, это нужно проверить на том ПК.

Проверки 0.4.2: независимые Qt_5_5-векторы для питания, сайта и файловых сообщений; порядок/содержимое бинарных блоков, отмена и предел неизвестного размера; HTTP(S)-валидация и безопасное имя файла. Браузерный стенд: 5/30 ПК, фактические рамки 16:9, полноширинные строки, все шесть массовых команд только по отображаемому фильтру, отдельная ошибка получателя и отмена, продолжение кадров после блокировки, пауза миниатюр в просмотре/управлении. Скриншоты `v042-*-synthetic.png` синтетические. Реальные power/site/file и framebuffer заблокированного Windows Veyon требуют проверки в классе; автоматические тесты ничего не отправляют реальным ПК.


## Стабильный выпуск 1.0.0: выбор отображаемых компьютеров

Пользователь подтвердил работу 0.4.2. Версия 1.0.0 публикуется как обычный стабильный GitHub Release (не prerelease) и назначается latest. Android package и сертификат сохранены, versionCode 9: установите APK поверх основной 0.3.x / 0.4.x, не удаляя её. Настройки VPN и ключи Veyon остаются на месте.

В верхней строке класса нажмите **ПК ▾**. В выпадающем списке отметьте нужные компьютеры. Поиск работает по имени и IP, «Все» возвращает весь список, «Снять все» убирает все миниатюры. Выбор применяется сразу и сохраняется в зашифрованных настройках устройства, независимо от параметров доступа Veyon. В счётчике отображается число плиток после всех фильтров.

Список флажков содержит компьютеры выбранной сети, включая офлайн-ПК (они выделены приглушённым цветом). Настройка «Только включённые ПК» продолжает ограничивать саму сетку. При первоначальном режиме «Все» новые компьютеры показываются автоматически. В индивидуальном режиме новые компьютеры нужно отметить вручную; отмеченные офлайн-компьютеры сохраняются в выборе и возвращаются в сетку при появлении онлайн.

Скрытый ПК не запрашивается очередью миниатюр и не входит в новую массовую команду. При изменении выбора текущий запрос миниатюры отменяется, затем очередь запускается для нового набора. В ходе массового действия флажки временно отключены: адресаты уже зафиксированы подтверждённым списком. Просмотр одного ПК по-прежнему останавливает остальные миниатюры.

Браузерная проверка: выбор двух ПК из тридцати, поиск, пустой выбор, возврат всех, восстановление после перезагрузки интерфейса, отсутствие запросов скрытых ПК и отправка общего сайта только двум выбранным получателям. Все прежние проверки 16:9, групповых команд, блокировки и режима просмотра также пройдены на синтетическом стенде. Кадры `v100-*-synthetic.png` синтетические.
