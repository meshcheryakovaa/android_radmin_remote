# Этап 2: панель класса и Veyon

Основное приложение 0.4.0 подключается прямо к уже установленному Veyon Service (по умолчанию TCP 11100) по виртуальному адресу компьютера 26.x.x.x. Radmin VPN / OpenRad / встроенный Xray продолжают обеспечивать сеть. Новый сервер, WebAPI или websockify для этой реализации не требуются.

## Первый запуск на одном ПК

1. Обновите основное приложение 0.3.0 этим основным APK 0.4.0: package и постоянный сертификат те же. Тестовая установка с другим package обновлением основной не является. Не удаляйте рабочее приложение ради установки.
2. Подключите VPN как раньше, выберите рабочий gRPC-профиль и войдите в Radmin-сеть. Дождитесь канала CONNECTED и PING до нужного ПК.
3. На ПК проверьте, что работает Veyon Service. В Veyon Configurator посмотрите порт сервера и способ аутентификации (ключ или logon). Подключение к Radmin Server на его порту — другой протокол; в этой версии используется Veyon.
4. В приложении: **Класс → Доступ к Veyon**. Для ключевого входа укажите имя ключа как на ПК, нажмите «Импорт приватного ключа», выберите экспортированный с компьютера учителя RSA PEM-файл, затем сохраните настройки. На целевом ПК должен быть соответствующий публичный ключ и разрешён доступ. Поддерживаются незашифрованные PEM PKCS#1 и PKCS#8; публичный ключ вместо приватного не подходит.
5. Для logon выберите «Учётная запись Windows», укажите пользователя и пароль, сохраните. На ПК должен быть включён этот метод, а учётная запись должна проходить обычные правила доступа Veyon. Блокировки и подтверждение доступа на компьютере не обходятся. Пароль Radmin-сети сюда не подходит.
6. Нажмите «Просмотр» на карточке ПК. Первый кадр означает, что протокол, аутентификация и доступ к рабочему столу прошли. По умолчанию ввод отключён.
7. Нажмите «Включить управление». Касание/щелчок передаёт левую кнопку, движение с удержанием — перетаскивание. Есть правая кнопка, колесо, аппаратная клавиатура, экранные Esc/Tab/Enter/Backspace/Win/Ctrl+Alt+Del и поле ввода текста. Для большого рабочего стола удобно горизонтальное положение планшета. Работа системных сочетаний и ввода Unicode зависит также от версии Veyon/UltraVNC и Windows; требуется проверка на ПК.
8. «Вернуться к классу» отключает управление, оставляя наблюдение. «Отключить» у карточки закрывает её сеанс, «Остановить экраны» закрывает все. Уход приложения в фон закрывает экраны; VPN-сервис при этом продолжает работать.

## Если нет соединения

Проверьте порт Veyon Service, службу и правила брандмауэра. На ПК с PowerShell можно посмотреть слушающий порт:

```powershell
Get-NetTCPConnection -LocalPort 11100 -State Listen
```

Если требуется новое правило для VPN-подсети, выполните на целевом ПК от администратора:

```powershell
New-NetFirewallRule -DisplayName "Veyon over Radmin VPN" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 11100 -RemoteAddress 26.0.0.0/8 -Profile Any
```

При нестандартном порту замените 11100. Не отключайте брандмауэр целиком. Отсутствие доступа Veyon после успешного PING не означает поломку VPN: проверьте имя ключа, публичный ключ на ПК, logon-данные, группы доступа и диалог подтверждения.

## Панель

Все компьютеры берутся из текущих сетей OpenRad; список не синтетический. Фильтры по Radmin-сети, имени/IP, подключённым каналам; размер плиток; выбор ПК. «Онлайн» здесь означает подключённый канал Radmin, а не уже пройденный вход в Veyon. Состояния экрана и канала разделены. Пустые плитки не подменяются картинкой рабочего стола. До четырёх выбранных экранов одновременно и один управляемый сеанс; на малом объёме памяти или большом разрешении лимит кадрового буфера может сработать раньше. Автоматическое подключение сразу ко всем 41 компьютеру не выполняется.

Обычные TCP-сокеты Veyon НЕ проходят через protect(): они идут в маршрут 26/8 уже установленного TUN. Доступны только выбранные RID текущих подключённых peers, не произвольный HTTP/TCP endpoint. Смена поколения VPN или уход Activity в фон аннулирует сеансы. Новое поколение Activity не переиспользует прежние сеансы. При выключении управления/закрытии отправляется отпускание клавиш и кнопок; при обрыве сети доставку отпускающих событий невозможно гарантировать. Закрытие имеет короткий принудительный срок и не выполняется в главном потоке Activity.

## Протокол и данные

Оригинальная реализация Kotlin, без включения кода/изображений GPL Veyon в APK. Ориентир интерфейса и первичный источник wire-контракта: [classroom_os](https://github.com/meshcheryakovaa/classroom_os) @ `63e840262cb02dd4bd74884dc69269589d191d19` (форк Veyon, GPL-2.0-or-later). Изучены RfbVeyonAuth, VeyonConnection, VariantStream/VariantArrayMessage, VncServerProtocol и ServerAuthenticationManager. Совместимость реализована независимо, исходники форка не изменены.

RFB 3.7/3.8, security type 40; Qt_5_5 QVariant subset (int, QString UTF-16BE, QByteArray), аутентификация RSA/SHA-512 challenge 128 bytes либо RSA-OAEP/SHA-1 для пароля. Нет downgrade на RFB None/VNC Password. Учётная запись, пароль и приватный ключ сохраняются только в EncryptedSharedPreferences/Android Keystore; они не возвращаются в HTML, диагностику или логи. Поле пароля очищается после отправки. Серверные сообщения ошибок не выводятся произвольным текстом. Кадры только в RAM, выдача JPEG через закрытый appassets origin с no-store; входящий clipboard игнорируется.

RGB565 little-endian; raw, copyrect, streaming zlib, DesktopSize/LastRect. Запросы кадров ограничены по частоте, размерам/памяти; непрошенные кодировки и некорректные сообщения закрывают сеанс. Системные функции Veyon (рассылка файлов, демонстрация учителя, выключение/блокировка ПК и т. п.) в этот этап не включены.

## Проверки

Протокольные JVM-тесты: независимые Qt_5_5 wire-векторы, ключевой и logon handshake с локальным синтетическим peer, SHA-512 подпись и RSA-OAEP расшифровка, raw/две последовательные zlib-области/copyrect, pointer/key wire events, feature-message framing, ограничение недоверенных длин и прямоугольников, отказ от downgrade, очистка пароля и валидация PEM. Три отдельных теста input gate проверяют отсутствие пакетов при просмотре/закрытии view-only, отпускание удерживаемых клавиш/мыши и продолжение очистки после сетевой ошибки. Qt-векторы получены настоящим QDataStream PySide6/Qt 6.12.0 с установленной версией потока Qt_5_5; этот инструмент не включается в APK.

Playwright-проверки интерфейса на 1280/390/320px используют явно синтетические desktop fixtures: фильтры, четыре выбранных экрана, отсутствие ввода при просмотре, явное управление, координаты при letterboxing, клавиатура, очистка пароля и отсутствие горизонтального переполнения. Screenshots `v040-*-synthetic.png` — тестовый стенд, не реальные ПК.

Автотесты не подключаются к реальной сети пользователя и не заменяют проверку с установленным Windows Veyon. Этот первый выпуск этапа 2 публикуется как prerelease для такой приёмки.
