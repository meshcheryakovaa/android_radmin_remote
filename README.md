# Android Radmin Remote

**Версия 0.4.0:** единый Android APK с локальным HTML-интерфейсом, OpenRad engine и встроенным Xray для **VLESS + Reality по TCP и gRPC**, с просмотром и управлением ПК через **Veyon**.

Android 8.0+ (API 26). DIRECT, внешний SOCKS5 или импорт серверов из Xray/Happ JSON. Единственный VpnService создаёт TUN с маршрутом `26.0.0.0/8`, MTU 1500. Остальной интернет телефона через этот TUN не направляется.

## Основное приложение 0.4.0

Основной APK: `android-radmin-remote-0.4.0.apk`, название **Radmin Remote**, package `ru.meshcheryakov.androidradminremote`, release-сборка без отладки. Проверенные TCP/gRPC, импорт Happ JSON, relay и исправление повторного запуска Xray включены. Протокол OpenRad и ограничения маршрута 26.0.0.0/8 сохранены. Пользователь подтвердил регистрацию, вход в сеть, четыре relay-соединения и RTT до ПК через gRPC-профиль на тестовой 0.2.1; это не гарантирует доступность любого сервера на любом операторе.

Обновление основной 0.3.0 сохраняет package, сертификат, VPN identity и настройки. Первое подключение к Veyon требует настройки доступа в новом разделе «Класс». Для перехода с исторических debug/test установок нужно установить основной APK отдельно и импортировать proxy-профили/войти в Radmin-сеть заново; такие установки можно оставить установленными.

Для основного выпуска подготовлен постоянный сертификат; SHA-256 в `release-signing-certificate.sha256`. Сам ключ не хранится в git. GitHub Actions публикует [релиз v0.4.0](https://github.com/meshcheryakovaa/android_radmin_remote/releases/tag/v0.4.0) только после настройки секрета. Если секрета нет, проверки и debug-артефакт собираются, но основной APK не публикуется. Инструкция: [подпись и публикация](docs/RELEASE-SIGNING.ru.md).

Исторический [тестовый релиз 0.2.1](https://github.com/meshcheryakovaa/android_radmin_remote/releases/tag/v0.2.1-test) остаётся доступен.

## Этап 2: управление через Veyon

**Класс**: плитки компьютеров, фильтры сети/имени/IP/онлайн, выбор до четырёх экранов; **Просмотр → Включить управление** для мыши/клавиатуры. Прямой доступ к установленному Veyon Service по TCP 11100, вход по приватному ключу Veyon или учётной записи Windows. Нужны права доступа Veyon на компьютере. Дополнительный агент и WebAPI не требуются. Рабочий VPN этапа 1 сохранён.

Начните с одного ПК: **Класс → Доступ к Veyon → выбрать способ входа, указать данные/импортировать ключ → Сохранить → Просмотр**. Пустая карточка не означает наличие Veyon-сеанса: сначала должны пройти аутентификация и получение кадра. По умолчанию ввод выключен. Первый выпуск этапа 2 требует проверки на вашем Windows Veyon; автоматические проверки используют синтетический peer.

[Настройка ПК, управление, ограничения и проверки этапа 2](docs/REMOTE-0.4.ru.md).

## Первый запуск VLESS / Reality

1. Установите APK. Отключите Happ и другие VPN-приложения.
2. Откройте **Proxy → Импорт из Happ / Xray**.
3. Вставьте экспортированный JSON и нажмите **Импортировать JSON**. Либо нажмите **Выбрать файл** и откройте `.json` / `.txt` до 512 КБ.
4. Выберите режим **VLESS + Reality · внутри APK**, затем нужный сервер из списка. Нажмите **Сохранить**.
5. На Главной нажмите **Подключиться**, разрешите Android VPN. Сначала запускается Xray и проверяется его внутренний SOCKS5-вход, затем OpenRad.
6. Дождитесь `CONNECTED`, адреса `26.x.x.x`, «TUN готов» и транспорта **VLESS / Reality**. В Proxy / диагностике Xray должен быть `READY`.
7. В **Сети** подключитесь к существующей Radmin VPN network. В **Устройствах** дождитесь peer `CONNECTED` и нажмите **PING**. В этом режиме ожидается `RELAY` с измеренным RTT.

Поддерживаются только outbounds `vless` + `reality` + `tcp` / `raw` / `grpc`. Балансировщик и правила маршрутизации Happ пока не импортируются. Приложение показывает количество импортированных профилей и пропущенных остальных записей. Повторный импорт заменяет список proxy-профилей, не затрагивая Radmin-сети и identity. Для изменения профиля сначала отключите VPN.

Импорт не выполняет исходную конфигурацию целиком: используются только проверенные поля выбранного профиля. Приложение создаёт собственный loopback SOCKS5 с непостоянным паролем, без дополнительного TUN и без отдельного Happ.

## Мобильная сеть с белыми списками

Работа сайтов через Happ AUTO не доказывает доступность выбранного в этом приложении сервера: AUTO может переключиться на другой TCP или gRPC узел. В Happ выберите конкретный сервер вручную и проверьте его на той же раздаче. Затем отключите Happ и выберите этот сервер здесь. Оба VPN одновременно не запускайте.

После обновления с 0.2.0 повторно импортируйте JSON: ранее gRPC-записи пропускались. Для конфигурации из двух TCP и трёх gRPC узлов ожидается пять профилей. Если рабочий узел неизвестен, проверяйте gRPC-профили по очереди: отключиться → выбрать → сохранить → подключиться. AUTO и fallback не воспроизводятся.

При смене домашнего Wi-Fi на раздачу отключитесь и подключитесь заново. В 0.2.1 новый запуск сначала закрывает предыдущий engine/TUN/Xray и обновляет native DNS. Это предотвращает повторный старт оставшегося READY ядра (`IllegalStateException`). Сам `Connection reset` не указывает, кто сбросил соединение; доступность сервера в условиях ограничений требует проверки на устройстве.

## DIRECT и внешний SOCKS5

Для DIRECT выберите соответствующий режим и подключитесь. Для внешнего SOCKS5 укажите сервер/порт и при необходимости логин/пароль. В SOCKS5 и Xray режимах OpenRad использует TCP relay; прямые peer TCP/UDP отключены. DIRECT сохраняет upstream-политику OpenRad: direct TCP/UDP по Wi-Fi, relay на остальных подключениях.

Кнопка «Проверить» для Xray оценивает уже установленную аутентифицированную control-сессию OpenRad. Она не считает один ответ локального SOCKS5 доказательством доступности VLESS-сервера. Полный критерий — `CONNECTED`, готовый TUN и PING до ПК. Для внешнего SOCKS5 проверяется CONNECT к координатору; сама проверка не выполняет вход Radmin.

## Сборка

JDK 17, Python 3, curl, Android SDK 34 / build-tools 34.0.0:

```bash
./scripts/setup-android-sdk.sh  # Linux, если SDK ещё нет
python3 scripts/setup-xray.py  # официальный AAR, SHA-256 проверяется
./gradlew :app:testDebugUnitTest :app:assembleDebug --no-build-cache
```

Загрузка AAR также автоматически выполняется Gradle task `setupXray`. AAR не хранится в git; URL, версия и SHA-256 зафиксированы в скрипте. Android Studio открывает корень проекта; Windows использует Python 3, curl и `gradlew.bat`. Результат: `app/build/outputs/apk/debug/app-debug.apk`. Для основной release-сборки настройте OPENRAD_SIGNING_PROPERTIES и выполните :app:assembleRelease.

GitHub Actions собирает APK, запускает JVM-тесты и native smoke test на loopback, публикует подписанный основной выпуск при настроенном секрете и debug-артефакт для разработки. DEX build cache отключён: при смене native classpath в AGP 8.5 локально наблюдались устаревшие архивы R-классов. Incremental/up-to-date проверки остаются доступны.

## Проверки и ограничения

Регистрация, вход в сеть, прямой TCP-канал и RTT уже были подтверждены пользователем на версии 0.1.1. Новая интеграция Xray проверяется синтетическими JVM-тестами, сборкой Android, проверкой HTML и запуском native Linux core с конфигурацией, сгенерированной тем же Kotlin-компилятором профилей. Это **не заменяет проверку VLESS/Reality на реальном Android и сервере провайдера**. Пользовательские серверы и данные доступа не используются в автоматических тестах.

Автобалансировщик Happ и обновление подписки по URL не реализованы. Удалённый рабочий стол добавлен через Veyon (см. этап 2). Пароли proxy, UUID и параметры профилей сохраняются через Android Keystore / EncryptedSharedPreferences, не возвращаются в HTML и не попадают в экспорт диагностики. Поле исходного JSON очищается после успешного импорта.
